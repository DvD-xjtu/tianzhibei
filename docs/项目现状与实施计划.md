## 1. 事项一：以两版 MTARSI 为前景素材的 Copy-Paste

### 已确认的约束

MTARSI-fixed 和 MTARSI-INNAR 在本机均为**分类图像目录**，没有实例 mask、HBB 或 OBB。它们不能直接作为严格实例 Copy-Paste 的“已抠出前景”。必须先对每张分类图生成飞机前景 mask，并进行人工/规则质检；否则会把原始机场背景、阴影和邻机一同粘贴，导致伪标注边界不可信。

现有可复用实现为：`/root/tianzhibei/algorithm/rtmdet_obb/scripts/synth_copypaste.py`。它已经实现旋转框裁剪、随机旋转粘贴、羽化融合、边界检查、与已有框的 rotated-IoU 约束和 DOTA annfile 输出。该脚本的前提是源实例已有 OBB；本项目应复用其“粘贴/碰撞检查/审计”部分，并新增“分类裁剪图 → 前景 mask → 最小旋转外接框”的前处理。

### 建议流水线

1. **冻结来源与类别映射**：只用下表中与目标任务一致的 MTARSI 类；保存每张源图、原始 split、类别和 hash。
2. **前景提取**：以 SAM 类分割器生成候选 mask；用面积占比、触边率、连通域数、圆度/长宽比和人工抽检过滤。保留 `source_masks/*.png` 及 JSONL 质量记录。
3. **背景选择**：只从 LAE-1M 的训练 split 取背景；验证/测试背景绝不可用于合成训练。背景已有标注时，新增目标与所有已有目标的 OBB IoU 必须低于阈值（建议 0.05–0.10）。
4. **几何与成像融合**：按目标数据分辨率、GSD/像素尺寸分布采样缩放与旋转；使用 alpha/Poisson 融合，保留原始 mask 生成精确 OBB，再写入 YOLO-OBB 标签。
5. **质量门控**：拒绝出界、过小、粘贴后遮挡过多、与已有框重叠和色彩差异常的样本；每批导出前后对比拼图、类别数、实例数、缩放比例、失败原因统计。
6. **训练与验证隔离**：合成集仅加入训练；MAR20 的官方 test 不参与任何阈值选择。若从 MAR20 train 划出 val，按机场/地理组切分，避免同机场图像或同源素材泄漏。

### 初始消融建议

- 基线：LAE-1M 原始训练数据。
- A：仅 MTARSI-fixed 前景；B：仅 MTARSI-INNAR 前景；C：两者合并。
- 每种来源再做无融合 / alpha / Poisson 的小规模对照；先使用每背景 0–3 架、合成样本占每 epoch 10%–20%。
- 分别报告 MAR20 的 20 类 AP、目标子集 AP、以及不含合成图训练的回归情况。

注意：现有天智杯 Copy-Paste 历史实验曾出现“共享合成库含 fold 验证背景”的泄漏记录。因此本项目必须按 fold 或最终 train/val 划分**分别**生成合成数据，绝不共享跨验证集的背景或源清单。

## 4. 开始实现前需要冻结的决策

1. 训练标签空间：采用 15 类目标、MAR20 原生 20 类，还是保留“飞机”单类检测并另做细粒度分类；三者不能直接混用类别 id。
2. LAE-1M 背景范围：首轮建议只使用其训练 split，且排除已有飞机标签或严格 IoU 去冲突。
3. MTARSI mask 的人工验收比例、合成量上限和目标像素尺寸/GSD分布。
4. MAR20 验证协议：官方 test 只作最后一次评估；训练期验证集从 MAR20 train 按机场分组划分。
